# План форка Copilot: выделенный текст + Ctrl, локальная Ollama и существующий интерфейс

Дата: 30 октября 2026 года.

## 1. Цель и границы

Взять `Magerko/copilot` за основу нового самостоятельного Windows-приложения и перенести в него поведение нашего Ollama Overlay: **выделить текст в другой программе → нажать и отпустить одиночный Ctrl → получить короткий ответ в оверлее**.

Основной интерфейс, окно подсказок, настройки провайдеров и инфраструктура сессий остаются из Copilot. Из нашего приложения переносится механизм выделения, распознавание горячих клавиш, удобство коротких ответов и управление отменой. Это объединение возможностей в отдельном форке, а не изменение `projects/script` и не одновременный запуск двух полных приложений.

Рабочие решения для плана:

- Основная платформа — Windows 10/11 x64, как у обоих проектов.
- На чистой установке основной режим — «Выделенный текст». Голосовой режим сохраняется, включается отдельно; удаление ASR не требуется.
- В текстовом режиме не нужны микрофон, системный звук, whisper-модель, резюме или описание вакансии.
- Основной провайдер — локальная Ollama; предлагаемая модель `qwen3.5:9b`, если она установлена. Не подменять её молча другой моделью.
- По умолчанию один короткий ответ на одно выделение. Развёрнутый ответ — отдельное явное действие.
- Существующие облачные провайдеры остаются дополнительной возможностью. Для локального режима не включать автоматический переход в облако.
- Сначала реализуется текстовый сценарий. Одновременное прослушивание и выделение — последующий этап с отдельной проверкой конфликтов.
- В этой задаче создаётся план и локальный клон. Реализация функций, публикация GitHub-форка и выпуск установщика пока не выполняются.

### Важные особенности исходного Copilot

1. `src/main/index.ts`: обработчик `km:session:askTyped` при отсутствии сессии вызывает `startSession('practice')`. Далее `afterStart()` вызывает `asr.ensure()` и отправляет `km:capture` для запуска аудио. Поэтому простого вызова `askTyped` для нового сценария недостаточно.
2. `src/main/session/manager.ts`: `start()` задаёт `listening: true`; `handle()` для нового вопроса запускает `['say', 'points']`. Это два вида генерации, а не один минимальный ответ.
3. `src/main/session/coordinator.ts`: ручной текст уже проходит через `manual(..., typed)`, минуя необходимость голосового обнаружения вопроса, но trigger становится `typed`. Для выделения нужен свой источник события.
4. `src/main/context/prompt.ts`: формат `say` требует 15–35 слов и ответа от первого лица; наш промпт предпочитает краткий ответ на языке исходного текста. Это разные режимы, их нельзя незаметно смешивать.
5. `src/main/session/board.ts` уже защищает UI по `questionId`, `revision` и владельцу `answerId`. Эту защиту нужно сохранить.
6. `src/main/windows/windows.ts` создаёт оверлей с `focusable: false`. Следует сохранить это свойство и проверить реальное поведение на Windows.
7. `src/main/storage/settings.ts` использует объединение JSON с defaults; полноценную версионированную миграцию новых настроек нужно добавить.
8. `Ctrl+Alt+S` у нас открывает настройки, а в Copilot запускает снимок области. Это реальный конфликт, требующий явного решения.

Все перечисленные факты установлены чтением кода. Windows-приложения и их сборки в рамках подготовки плана не запускались; успешная работа в Windows пока не подтверждена.

## 4. Целевой пользовательский сценарий

1. Пользователь выбирает «Выделенный текст» при первом запуске.
2. Проверяет доступность Ollama, выбирает уже установленную модель. Если модели нет, интерфейс показывает понятную причину; загрузка не начинается молча.
3. Видит состояние «Готов к выделению», а для микрофона и ASR — «Выключено».
4. Выделяет текст в браузере, редакторе или другом приложении.
5. Нажимает и отпускает Ctrl без других клавиш.
6. Приложение читает выделение, не переводя фокус в свой интерфейс, и отправляет один запрос.
7. Оверлей показывает короткий ответ; полный текст доступен отдельно и копируется целиком.
8. Одиночный Escape скрывает ответ; два отдельных нажатия в пределах 400 мс отменяют текущую операцию. После первого Escape завершившийся новый ответ может появиться, как в нашем приложении; после отмены — нет.
9. `Ctrl+Alt+X` отключает рабочие горячие клавиши и отменяет запрос. Повторное сочетание включает их, но не возобновляет отменённую работу. `Ctrl+Alt+U` завершает приложение.

На время реализации зафиксировать поведение повторной отправки: пока идёт чтение/генерация, повторный Ctrl показывает «Запрос выполняется» и не создаёт очередь. Для замены вопроса сначала отменить текущий запрос. Голосовой режим сохраняет свою существующую логику смены вопросов.

## 5. Архитектура

```text
Чужое Windows-приложение
  → клавиатурный hook и чтение выделения в Windows helper
  → локальные stdin/stdout сообщения
  → SelectionService в Electron main
  → SessionManager.submitSelection
  → выбранный provider через существующий runner
  → AnswerBoard
  → существующий React-оверлей
```

Голосовой путь остаётся отдельным входом в SessionManager. Сетевые запросы, провайдеры и состояние ответа принадлежат Electron main; helper не выполняет запросы к модели и не рисует окна.

### Почему отдельный helper

Рекомендуемый первый вариант — небольшой Python helper, собранный в Windows exe. Он позволяет перенести наш механизм UI Automation и распознавания клавиш, не добавляя сразу новый нативный Node addon и его привязку к версии Electron.

Это архитектурный выбор для будущей реализации, а не уже существующий компонент. В первой технической пробе проверить задержку, COM/UIA, упаковку, запуск без установленного Python и корректное завершение helper. Если упаковка или надёжность неприемлемы, заменить только helper на C#/C++ с тем же протоколом; не переписывать UI и SessionManager.

Не копировать всё приложение: выделить необходимые части из `platform/windows/{hotkeys,selection,win32}.py`, адаптировать зависимости на конфигурацию и события. Проверить все транзитивные импорты. Tkinter, Pillow, HTTP-клиент и наше окно настроек в helper не нужны.

## 6. Windows: клавиши и выделение

### Распознавание клавиш

- Перенести конечный автомат `KeyRecognizer`, который учитывает весь цикл нажатия и отпускания, повторы, левый/правый Ctrl и сочетания.
- Не считать одиночный modifier обычным Electron accelerator: для требуемой семантики нужен поток down/up-событий и контроль других нажатых клавиш.
- Ctrl+C/V/A/Z, Ctrl+Shift, AltGr и удержание Ctrl не должны отправлять вопрос.
- Не блокировать обычные клавиши в приложении пользователя.
- Собственные синтетические Ctrl+C не должны повторно активировать отправку.
- На время редактирования сочетаний отключать их действия; назначение клавиши выхода не должно закрывать приложение.
- Единый владелец каждого сочетания: helper для release-семантики и Esc, Electron для остальных действий. Не регистрировать одно сочетание в обоих механизмах.
- В окнах самого Copilot не запускать чтение внешнего выделения; штатное редактирование и Escape в диалогах должны работать.

### Чтение выделения

1. Зафиксировать HWND активного внешнего окна при срабатывании команды.
2. Читать выделение через UI Automation TextPattern в ограниченном по времени worker.
3. Проверять, что активное окно не изменилось до и после чтения.
4. При отсутствии UIA-выделения использовать резервный Ctrl+C, дождавшись отпускания модификаторов.
5. Отправлять только результат нового копирования: сравнивать clipboard sequence до/после, исключать отправку прежнего буфера.
6. Сохранить существующее поведение fallback: скопированное выделение остаётся в буфере; не очищать буфер и не восстанавливать его только как plain text, теряя изображения/HTML.
7. Пустое выделение и смена фокуса завершаются без LLM-запроса.
8. Если UIA распознал защищённое поле, возвращать отдельный запрещающий статус без fallback. Текущее пустое значение из UIA не различает этот случай — при переносе это нужно исправить.
9. Не пытаться обходить границы привилегий Windows; невозможность чтения из повышенного процесса показывать как ограничение, не запускать helper администратором автоматически.
10. Ограничить одно активное чтение; при зависшем UIA не плодить потоки бесконечно. После таймаута и отмены отбрасывать результат; при невосстановимом зависании перезапускать helper ограниченное число раз.

Первоначально перенести текущие значения таймаутов: UIA 0,8 с, ожидание модификаторов 0,8 с, clipboard до 1,5 с, подавление событий после копирования 0,25 с. Это исходные настройки, которые предстоит измерить на Windows, а не обещанные задержки.

### Контракт helper ↔ Electron

Транспорт — JSON Lines через выделенные stdin/stdout дочернего процесса, без TCP-порта и shell-команд. Диагностика — stderr, без содержимого текста.

- Handshake: версия протокола, PID, список возможностей.
- Команды: configure, cancel, shutdown; события: ready, command, selection, error.
- Каждый результат чтения содержит `captureId`, эпоху отмены, метод `uia|clipboard`, текст либо код ошибки.
- HWND передавать строкой, не полагаться на точность JavaScript number для указателей.
- При отмене, остановке или новом подключении менять эпоху; результат из предыдущей эпохи никогда не отправляется модели.
- Проверять типы, максимальный размер строки и текста; начальный лимит текста 32 000 символов. Превышение объяснять, не обрезать молча.
- Частичные JSON-строки и несколько сообщений в одном chunk обрабатывать корректно.
- При закрытии stdin helper снимает hook и завершается. Electron при выходе ждёт короткий grace period, затем завершает оставшийся дочерний процесс.

## 7. Текстовая сессия без аудио

Изменить `src/shared/types.ts`, `src/main/session/{manager,coordinator}.ts`, `src/main/index.ts` и интерфейс API.

1. Добавить `InputMode = 'selection' | 'voice' | 'hybrid'`; для первого релиза активны selection и voice, hybrid скрыт до готовности.
2. Не смешивать InputMode с существующим `practice|live|meeting`: один описывает источник ввода, другой — назначение сессии.
3. Ввести текстовое состояние готовности, не выдающее ложное «Слушаю»; `listening` отражает только фактическое разрешение аудиопути.
4. Разделить создание сессии и `afterStart`: текстовый старт не вызывает `asr.ensure`, `km:capture/start` или неявную загрузку моделей ASR.
5. Добавить явный `submitSelection(text, captureId)`; выделение проходит как прямой запрос без голосового classify/dedup/склейки фраз.
6. Добавить trigger `selection`, сохранив смысл существующего Source `user|remote`. Обновить все потребители enum, историю и экспорт.
7. Для выделения запускать один ответ, переиспользуя `say` с отдельным prompt preset. Не создавать `points` автоматически. Это минимизирует изменения типов AnswerKind.
8. Отдельный развёрнутый ответ использует тот же вопрос и текстовый prompt preset, без автоматического перехода к интервью-промпту.
9. Остановка/отключение hotkeys отменяет и чтение, и транспорт. После отмены инвалидировать владельца AnswerBoard, чтобы поздние chunks не вернули ответ.
10. Переход voice → selection останавливает захват и ASR; переход selection → voice запускает звук только после пользовательского выбора и существующих разрешений.
11. Для текстовой сессии не подмешивать голосовой transcript, старые вопросы и CV по умолчанию. Контекст интервью — отдельная настройка.
12. Обновить восстановление сессии, tray, diagnostics и outgoing preview: восстановление текстовой сессии также не включает микрофон.

## 8. Ollama и формирование ответа

### Ключевое различие

У нашего приложения native `/api/generate`, `think: false`, температура 0, таймаут подключения 5 с и общий таймаут 300 с. У Copilot Ollama использует OpenAI-compatible endpoint. Совпадение адреса сервера не означает одинакового payload и поведения модели.

### Последовательность

1. Для ранней проверки цепочки использовать существующий Ollama preset Copilot.
2. Для переноса нашего поведения добавить `ollama-native.ts`, расширить factory/registry и тип протокола. Обновить все исчерпывающие switch/Record.
3. В текстовом режиме native-адаптер должен воспроизводить наш prompt + выделение через `/api/generate`; не превращать его незаметно в другой chat template.
4. Поддержать stream NDJSON: `response`, `done`, server error, неполную строку, повреждённый JSON, EOF без done, пустой ответ и AbortSignal.
5. `think` передавать только native-адаптеру: false/true/по умолчанию. Не пересылать этот параметр произвольным облачным API.
6. Список моделей для native-адаптера получать через `/api/tags`; ошибки показывать явно.
7. Маршрутизировать запросы через существующие сетевые ограничения, runner и учёт запросов; не создавать обходной fetch вне этой инфраструктуры.
8. Выделить настройку провайдера/модели именно для selection, чтобы голосовые роли не переключались неожиданно.
9. Отдельный редактируемый промпт, восстановление исходного текста, температура и таймауты. Исходный текст взять из `projects/script/src/ollama_overlay/config/defaults.py` на момент реализации.
10. Требование «на языке исходного текста» оставить в промпте; существующее определение языка Copilot ограничено ru/uk/en и ошибочно классифицирует, например, болгарский как русский. Для selection не навязывать этот классификатор.
11. Полный ответ хранить в памяти целиком. 300 символов — настраиваемое ограничение показа, а не обрезка ответа/истории; при сокращении показывать возможность раскрыть.
12. Не обещать побайтово одинаковый ответ LLM; проверять входной payload, параметры, количество запросов и поведение управления.

## 9. Интерфейс и настройки

### Первый запуск

В `Onboarding.tsx` добавить выбор ввода до аудиошагов. Для selection маршрут: язык → Ollama/провайдер → проверка выделения и Ctrl → готовность. Шаги устройств, ASR и загрузки резюме пропускаются, доступ к ним остаётся в настройках.

### Главная страница и оверлей

- Статусы: «Готов к выделению», «Читаю выделение», «Генерирую», «Нет выделенного текста», «Ollama недоступна», «Горячие клавиши отключены».
- Показать активный режим и выбранную модель.
- Не отображать неиспользуемый ASR как ошибку настройки.
- Полный ответ открывается в обычном фокусируемом окне/разделе, где можно редактировать текст, копировать и повторно показать; не делать нефокусируемый оверлей текстовым редактором.
- Отдельные действия «Скрыть» и «Отменить».
- Сохранить тему, прозрачность, размер шрифта и положение окна Copilot. Точное воспроизведение всех Win32-координат/шрифтов нашего overlay не является условием MVP.

### Горячие клавиши

| Действие | Предлагаемое значение |
|---|---|
| Отправить выделение | одиночный Ctrl после отпускания |
| Настройки | Ctrl+Alt+S |
| Отключить/включить рабочие hotkeys | Ctrl+Alt+X |
| Полный выход | Ctrl+Alt+U |
| Скрыть / отменить | Esc / двойной Esc за 400 мс |
| Показать/скрыть оверлей | существующее Ctrl+Alt+H |
| Снимок области, если нужен | перенести на Ctrl+Alt+P с проверкой конфликта |

Существующие назначения пользователей не перезаписывать молча: при миграции показать конфликт настроек/снимка и предложить выбор. Новые defaults применяются только к чистой установке.

### Сохранение и импорт

- Версионировать новые настройки; повреждённую/будущую схему не заменять defaults с последующей потерей файла.
- Записывать атомарно, делать резервную копию перед миграцией.
- Добавить ручной импорт нашего `settings.json`/старого `overlay_settings.json`, предварительный просмотр и список неперенесённых полей.
- Импортировать адрес, модель, промпт, temperature, think, таймауты и совместимые hotkeys; единицы таймаутов переводить явно.
- Параметры внешнего вида переносить только при семантическом соответствии; остальные оставить в отчёте импорта.
- Не читать и не менять настройки установленного старого приложения автоматически.
- По умолчанию историю выделений и ответов не сохранять на диск; при включённой истории использовать существующий согласованный путь хранения.
- В логах оставлять коды ошибок/длительности/идентификаторы, но не текст выделения, ответы или секреты.

## 10. Этапы реализации и критерии завершения

| Этап | Работа | Проверяемый результат |
|---|---|---|
| 0. База | Ветка, upstream/origin, фиксация версии, baseline проверки | Чистая сборка исходного Copilot либо документированные исходные ошибки |
| 1. Техническая проба | Минимальный helper: одиночный Ctrl, UIA/fallback, JSON Lines | На Windows чтение реального выделения без кражи фокуса; Python на машине не требуется |
| 2. Текстовая сессия | InputMode, submitSelection, один ответ, отсутствие audio-start | Текстовый ввод работает без микрофона и файлов whisper |
| 3. Надёжность | Отмена, epochs, лимиты, focus guards, авария helper | Старый текст/старые ответы не попадают в новый запрос/UI |
| 4. Ollama/промпт | Native-адаптер и параметры нашего приложения | Контрольный сервер подтверждает endpoint/payload, один запрос и отмену |
| 5. UX | Onboarding, InputTab, статусы, полный ответ, конфликты hotkeys | Основной сценарий доступен с чистой установки |
| 6. Совместимость | Миграции, импорт, голосовые регрессии, восстановление | Старые настройки сохраняются; voice работает отдельно |
| 7. Доставка | Helper в installer, CI Windows, документация | Установка и запуск на чистой Windows без Python/Node |
| 8. Позднее | Hybrid, оптимизация задержки, дополнительные стили | Отдельные критерии очередности голосовых и текстовых вопросов |

Ориентировочный порядок по времени для одного разработчика: база и проба 1–2 дня, интеграция/отмена 2–4 дня, провайдер и UI 2–3 дня, Windows-регрессии/упаковка 2–4 дня. Это диапазон 7–13 рабочих дней, не обещание срока; после первой Windows-пробы оценку пересмотреть.

## 11. Проверки

### Baseline и CI

В каталоге форка:

```bash
npm ci
npm run typecheck
npm test
npm run build
```

Использовать Node 24, как в существующих workflows. Зафиксировать реальный вывод baseline; число тестов в README не считать доказательством текущего прохождения. На Linux можно проверить TypeScript, логику и bundle; реальные Windows hooks и взаимодействие с окнами там не проверяются.

### Автоматические проверки новых механизмов

- Распознаватель: одиночный Ctrl, Ctrl+C/V/A/Z, auto-repeat, обе стороны Ctrl, AltGr, смена раскладки, запись сочетаний, собственный Ctrl+C.
- Clipboard: старый текст не отправляется; новая копия с тем же содержимым допустима по sequence; смена фокуса, занятый clipboard, пустое выделение, таймаут и protected field.
- Bridge: частичные сообщения, неверная версия/JSON, oversized payload, EOF, падение процесса, поздний captureId и отмена.
- Session: selection не вызывает ASR/capture; одно выделение даёт один запрос; busy не создаёт очередь; повторный явный вопрос после завершения допускается.
- Cancellation: отмена во время UIA, clipboard, подключения и streaming; поздний ответ не восстанавливает скрытое/отменённое состояние.
- Provider: корректный native payload, `think`, timeout, недоступная модель, EOF без done, отсутствие cloud fallback.
- Настройки: defaults, миграция, будущая версия, повреждённый JSON, конфликт клавиш, импорт секунд в миллисекунды.
- Голос: прежние тесты coordinator/manager остаются рабочими; изменённые состояния не ломают ответы и восстановление.

### Ручная матрица на Windows

1. Windows 10/11, запуск без повышения привилегий.
2. Браузер, Блокнот, VS Code, Word/PDF-просмотрщик с доступным текстом: проверить фактическое чтение и используемый метод. Скан PDF без выделяемого текста не является поддерживаемым selection-сценарием.
3. Пустое выделение при непустом старом буфере: ноль запросов.
4. Ctrl+C/V/A не вызывает запрос, ввод в исходном окне продолжается без переключения фокуса.
5. Выключенная Ollama, отсутствующая модель, медленный первый токен, обрыв потока и отмена.
6. Длинный вопрос/ответ, Unicode, русский, болгарский, немецкий, несколько мониторов и масштабирование 125–200%.
7. Сворачивание в tray, повторный запуск, выход, отсутствие осиротевшего helper и клавиатурного hook.
8. Чистая Windows без Python/Node и без whisper: selection работает при отдельно установленной Ollama.
9. Голосовой режим после переключения работает; возврат к selection останавливает аудио. Закрытый доступ к микрофону не мешает selection.
10. История выключена: выделения/ответы отсутствуют в логах и файлах данных. При включении сохраняется только ожидаемая история.

Фиксировать версии Windows/Ollama/модели, фактические результаты, время чтения, время первого токена и завершения. Не объявлять поддержку приложения только по unit-тесту.

## 12. Сборка, установка и откат

- Windows workflow сначала собирает helper с зафиксированными Python/зависимостями, затем выполняет typecheck, tests, bundle и electron-builder.
- Поместить helper через `extraResources` вне ASAR; main выбирает dev/release путь, проверяет существование и версию протокола.
- Установщик содержит необходимые helper runtime-файлы; отдельный Python пользователю не нужен. Ollama и модель остаются внешними зависимостями.
- Исправить release workflow: сейчас package.json использует Copilot, а текст публикации упоминает Kairos M. Для форка имя артефакта и инструкции должны совпадать.
- Не переиспользовать существующий URL загрузки нашего Overlay или его install/rollback скрипты: у нового приложения отдельная доставка.
- Не менять `OLLAMA_MODELS` и не перезапускать/переустанавливать общую Ollama ради установки форка.
- Добавить Windows smoke-check packaged helper и сохранения настроек после обновления; сохранить текущие Linux-проверки переносимой логики.
- Релиз снабдить SHA-256, описанием изменений и известными ограничениями.
- Откат: остановить форк/helper, восстановить предыдущую сборку и резервную копию настроек при необходимости. Наш `projects/script` и его установленная версия остаются независимыми.

## 13. Основные риски и решения

| Риск | Решение |
|---|---|
| UIA доступен не во всех программах | Проверенный clipboard fallback, диагностика метода и честная ошибка |
| Зависший UIA provider | Ограниченный worker, таймаут, инвалидация результата, перезапуск helper |
| Отправка старого clipboard | Проверка sequence и окна-источника; не читать буфер без новой операции копирования |
| Отмена не останавливает поздний ответ | Epoch для выделения и owner/revision для ответа |
| Голос запускается через typed API | Разделить старт сессии и audio lifecycle до подключения hotkey |
| Один вопрос порождает два запроса | Selection policy генерирует только say, deep по отдельному действию |
| Native и OpenAI-compatible Ollama отличаются | Явный протокол, payload-тесты, отдельные параметры think |
| Две системы hotkeys вызывают двойные действия | Общая таблица назначений и один обработчик на действие |
| Python helper усложняет установщик | Ранняя проба готового exe на чистой Windows; изолированный контракт |
| Изменения upstream конфликтуют с форком | Небольшие коммиты, отдельные input-модули, периодический merge upstream и регрессии |

## 14. Готовность первой версии

Версия готова, когда на чистой целевой Windows пользователь может выбрать локальную модель, выделить текст в другой программе, отпустить одиночный Ctrl и получить один короткий ответ в существующем оверлее Copilot. При этом звук не включается, фокус не меняется, старый clipboard не отправляется, отмена работает, полный ответ доступен, установка не требует Python, а голосовая функциональность остаётся доступна отдельным режимом.

Артефакты реализации: отдельный fork/ветка, исходники helper, изменения Electron-приложения, проверки, установщик, README и отчёт Windows-проверок. Ни один из этих результатов нельзя считать выполненным только на основании настоящего плана.

## Уточнение требований после повторного аудита (30.10.2026)

Исходный запрос сохраняется: изменять Copilot, переносить выделение + Ctrl, не менять projects/script. Дополнительное требование пользователя — один PowerShell-файл, устанавливающий всё. Публикация предварительно собранного exe остаётся отдельным вариантом доставки.

Нужны Windows x64, интернет, рабочий winget/App Installer и место для модели и сборки. Скрипт не гарантирует установку на машине, где package manager/сеть/запуск установщиков запрещены. Подготовленный скрипт и проверенный на Windows установщик — разные уровни готовности.
